# Troubleshooting: проблемы и решения

## 1. RestAssured vs HttpURLConnection в WSL

**Проблема:**  
При запуске теста на RestAssured возникал `NullPointerException`, хотя `curl` работал и сервер был доступен.

**Причина:**  
В WSL (Windows Subsystem for Linux) есть особенности работы с сетью (IPv4/IPv6). RestAssured, использующий Groovy и Apache HttpClient, в некоторых случаях не может корректно создать HTTP-клиент, 
что приводит к передаче `null` в метод `Class.isAssignableFrom()` — отсюда NPE.

**Решение:**  
Заменил RestAssured на стандартный `HttpURLConnection`. Он не зависит от Groovy и работает стабильно в любом окружении.

**Вывод:**  
В нестандартных средах иногда проще использовать базовые инструменты JDK, чем бороться с библиотечными багами.

## 2. Docker: порт не доступен извне

**Проблема:**  
После запуска контейнера с Spring Boot приложением, `curl localhost:8080` не работал, хотя контейнер был запущен.

**Причина:**  
Spring Boot по умолчанию слушает `localhost` (127.0.0.1), а внутри контейнера это не позволяет принимать запросы с хостовой машины.

**Решение:**  
Добавил в `application.properties` строку: server.address=0.0.0.0

После пересборки и перезапуска контейнера порт стал доступен.

**Вывод:**  
В контейнерах нужно явно указывать интерфейс для прослушивания (0.0.0.0), чтобы приложение принимало соединения извне.

## 3. Компиляция Java из командной строки

**Проблема:**  
При использовании `javac` с параметром `-d` возникала ошибка, если путь к папке не существовал.

**Решение:**  
Использовал `mkdir -p` для создания целевой папки перед компиляцией, либо указывал абсолютный путь.

**Вывод:**  
Всегда проверяйте, что выходная директория существует, или используйте флаг `-d` с уже существующим путём.
